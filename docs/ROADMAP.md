# Hydrology implementation roadmap

## Goal

Provide topographic flow-routing and rainfall-volume analysis using Copernicus GLO-30 initially, with support for later LiDAR-derived terrain. The GUI will eventually allow drawing arbitrary rainfall polygons, selecting rainfall depth/duration and effective-runoff assumptions, specifying maximum downstream travel distance, and inspecting flow paths, storage basins and possible overflow routes.

The initial rainfall-volume model is not a dynamic hydraulic solver: it predicts terrain-derived routing and basin storage/overflow volumes, not real-world arrival times, flow velocity, peak discharge or street-scale flood depth. A separate AOWIS-SERVER-SWMM service can later consume drainage/catchment results.

## Stages and exit tests

1. **Reliable foundation and reusable application service.** **Implemented in code:** job lifecycle/storage now live in `AOWIS::HydrologyService`, the REST adapter delegates to it, and the core supports cancellation checks. Synthetic service tests cover completion, persistence and cancellation. **Remaining verification:** compile and run the new Qt service/REST code, test HTTP-versus-library parity and exercise failure/restart behavior before this stage is considered complete.
2. **GeographicLib and raster geometry.** Core implementation completed for north-up EPSG:4326 and WGS84 UTM (zones 1–60): pinned GeographicLib 2.7 dependency setup, explicit CRS and vertical datum, ellipsoidal geographic distances/areas, projected UTM metrics, no forced GLO-30 reprojection. GeographicLib must still be registered as a Git submodule by running `tools/setup_geographiclib.sh` in the actual checkout; a changed-files ZIP cannot create a gitlink. Expanded core tests pass against GeographicLib 2.7. Rotated/sheared rasters and arbitrary projected CRS are deliberately deferred to LiDAR ingestion.
3. **Analysis-grade DEM ingestion.** **Implemented:** Map now owns native DEM window sampling via its `TerrainData::analysisGrid()` C++ API and matching `/terrain/v1/analysis/grid` HTTP endpoint (in the separately supplied Map patch). Hydrology uses them for standalone library and distributed deployments respectively. Its optional GDAL `AOWIS::HydrologyRaster` reader is retained only for tests/development. All regular server-side local DEM directory configuration has been removed. **Tests:** Map synthetic Copernicus windows, Hydrology GDAL fixtures, and injected terrain service jobs. **Remaining:** run a live Map→Hydrology REST end-to-end smoke test in the target Linux installation; source fingerprints and persistent catalog are later enhancements.
4. **DEM conditioning.** **Implemented (first increment):** physical Priority-Flood fill levels without artificial epsilon elevation ramps; topological plateau routing with deterministic sinks; Preserve/Fill routing modes; potential fill-depth raster, volume and metadata diagnostics. The original DEM remains independent of the routing surface. **Second increment implemented:** optional bounded, least-excavation *local* breaching at internal pits, explicit depth/path/volume/candidate budgets, cut-depth raster and accepted/rejected diagnostics; nested-basin and synthetic obstruction tests. **Remaining:** independent reference comparisons, robust multi-cell/wide-ridge breaching strategies, numerical policies for basin hierarchy, and larger real-data benchmarks. Details: [CONDITIONING.md](CONDITIONING.md). **Exit:** additional synthetic and external-reference tests for nested basins, flats, outlet and NoData behavior.
5. **Flow graph and downstream tracing.** **First increment implemented:** a Qt-independent D8 flow-graph query layer (bounded, metric downstream tracing and path slope, head/confluence/outlet channel topology, Strahler order, configurable upstream-area threshold, and bounded library/REST result APIs). Persisted jobs answer trace queries by random-access raster reads rather than loading the whole graph. **Second increment implemented:** raster-exact watershed MultiPolygons (holes and disjoint components), WGS84 polygon/multipolygon-to-downstream-influence selection, and spatially bounded channel extraction with explicit clipping and locally recalculated stream orders. **Remaining:** drainage-domain expansion, reference comparisons, spatial indexes and large-area performance tests. See [DRAINAGE_NETWORKS.md](DRAINAGE_NETWORKS.md).
6. **Depression hierarchy and storage curves.** **Core foundation implemented:** elevation-ordered 8-connected depression merge tree on immutable original elevations, plateau-aware minima, nested parent/child saddle relationships, spill capacities with numerically stable area-weighted accounting, and bounded water-level storage queries. Deterministic synthetic, randomized and numerical tests are included. **Second increment implemented:** checksum-validated persistent basin archive per completed terrain job, deterministic job-scoped UUIDs, paginated service/REST basin details, bounded water-level queries and sampled storage curves, tested after service restart. **Performance increment implemented:** geodesic/UTM per-row area reuse in hierarchy construction and lazy row reuse in bounded storage queries; identical basin capacities on geographic and projected regression fixtures, with synthetic benchmark improvement. **Remaining:** metropolitan memory benchmarks, further hierarchy profiling and independent reference comparisons. See [DEPRESSION_HIERARCHY.md](DEPRESSION_HIERARCHY.md).
7. **Rainfall input and scenario engine.** **Implemented and Linux Debug/Release tested:** Qt-independent WGS84 GeoJSON Polygon/MultiPolygon rainfall geometry on geographic/UTM rasters, cell-overlap and polygon-union volumes (including holes), total depth/duration/effective-runoff fraction validation, persisted UUID scenarios against existing terrain analyses, summary/volume balance, and bounded binary per-cell runoff output via C++ service and REST. Synthetic geometry and volume tests included. **Remaining:** metropolitan-volume/performance benchmarks, edge-case validation against reference GIS tools, and end-to-end HTTP integration verification. See [RAINFALL_SCENARIOS.md](RAINFALL_SCENARIOS.md).
8. **Fill–Spill–Merge-style redistribution.** **First increment implemented:** static, volume-conserving runoff transport on original, unfilled DEM flow paths; leaf depression retention and spill, deterministic sibling fill at merge saddles, parent basin storage and open-domain discharge. A transport-independent service method and REST endpoint report totals and UUID-addressed paginated basin states for saved rainfall scenarios. Synthetic and randomized monotonicity/mass-balance tests included. **Second increment implemented:** versioned, atomic, integrity-checked per-scenario redistribution caches; bounded random-access basin pagination; stale/corrupt cache reconstruction; post-restart reuse; dedicated format/operations guide and regression tests. **Third increment implemented:** bounded background redistribution worker queue, UUID task status, cooperative cancellation, nonblocking HTTP POST/status/GET/DELETE and cache-only result reads; the legacy synchronous C++ method remains for existing callers. **Fourth increment implemented:** conservative inversion of stored volumes to connected-root water levels and cell-centre standing-water depths, with explicit unavailability for unresolved partial sibling merges. **Fifth increment implemented:** asynchronous task/status/cancellation API, separately persisted depth rasters, source-fingerprint invalidation, checksum-verified bounded raster windows, restart recovery and REST/standalone service parity (see [STATIC_INUNDATION.md](STATIC_INUNDATION.md) and [INUNDATION_SERVICE.md](INUNDATION_SERVICE.md)). **Sixth increment implemented:** hierarchical reconstruction of separate pre-merge child-pond water levels, conditional allocation flagging through core/service/REST, nested-merge tests and v2 inundation caches. **Seventh increment implemented:** optional Qt-independent comparison of two shared-saddle sibling traversal orders, reporting leaf-volume differences while requiring identical overall retention and discharge; the cached default result is unchanged. See [SIBLING_ALLOCATION_SENSITIVITY.md](SIBLING_ALLOCATION_SENSITIVITY.md). **Eighth increment implemented:** opt-in Qt-independent remaining-capacity-weighted sibling overflow assignment; child-list order invariance, analytic three-pit tests, randomized conservation checks and a dedicated model-assumption guide ([CAPACITY_WEIGHTED_SIBLING_ALLOCATION.md](CAPACITY_WEIGHTED_SIBLING_ALLOCATION.md)). The standard persisted/index-ascending solver is unchanged and the weighted policy is explicitly heuristic. **Ninth increment implemented:** Qt-independent internal merge-saddle contact extraction from original DEM, with D8 cardinal/diagonal separation, WGS84/UTM raster-face metrics, and physically connected equal-height merge collapsing. No new flow-rate claim or default cache/API change. See [SPILL_GEOMETRY.md](SPILL_GEOMETRY.md). **Tenth increment implemented:** an opt-in, Qt-independent, explicitly parameterized rectangular broad-crested **free-overflow** control bound to a two-component cardinal saddle; water-head rating, deliberate refusal of submerged/multiway flow, and a one-step volume-conserving crest-limited transfer using externally supplied stage–storage curves. Does not modify default scenario caches/results, and is not a coupled dynamic basin model. See [SPILL_HYDRAULICS.md](SPILL_HYDRAULICS.md). **Eleventh increment implemented:** separately opt-in, explicitly calibrated broad-crested tailwater reduction (`K(r)` knots with validation/interpolation) and an equal-stage-limited, volume-conserving transfer step, plus a fully submerged rectangular opening rate with independently supplied invert and aperture geometry; unsupported partial opening is explicitly rejected. The original free-only API and all cached/default scenario results are unchanged. See [SUBMERGED_SPILL_CONTROLS.md](SUBMERGED_SPILL_CONTROLS.md). **Twelfth increment implemented:** experimental Qt-independent coupled finite-volume reservoir routing for externally supplied per-basin inflow intervals, simultaneous calibrated-weir/submerged-orifice controls, stage-storage inversion, adaptive step rejection, interval snapshots and water-balance verification. Unlike the static redistributor, this is a time-dependent lumped-reservoir numerical model; it requires independent hydraulic ratings and inflow hydrographs, does not infer them from DEM/rainfall totals, and is not yet exposed by HTTP. See [COUPLED_RESERVOIR_ROUTING.md](COUPLED_RESERVOIR_ROUTING.md). **Thirteenth increment implemented:** opt-in Qt-independent bridge from Stage 7 event-total effective-runoff raster through original-DEM dry D8 leaf inputs into the coupled solver's prescribed per-interval forcing, using an **explicit caller-supplied temporal profile**. It retains direct domain-boundary runoff separately and does not import static spill volumes; that adapter itself still has zero travel delay and no boundary outlet law (both now have separate opt-in extensions). See [TEMPORAL_RUNOFF_FORCING.md](TEMPORAL_RUNOFF_FORCING.md). **Fourteenth increment implemented:** an opt-in, Qt-independent free-overflow terminal domain-outlet model coupled simultaneously with internal hydraulic connections and per-interval prescribed inflows; new per-outlet cumulative discharge and globally conserved `storage + exterior discharge = initial storage + inflow` at every snapshot, with crest/depth/width validation, adaptive substep rejection and tests. The original closed-network API is unchanged; downstream submergence, exterior backflow and timed boundary stages are explicitly unsupported. See [BOUNDARY_OUTLETS.md](BOUNDARY_OUTLETS.md). **Fifteenth increment implemented:** a separate opt-in dry-D8 travel-time forcing adapter with a caller-specified constant routing speed, geodesic/UTM edge lengths, delayed rectangular runoff pulses, post-event arrival bins, explicit dry-boundary outputs and mass conservation against static leaf totals; no static cache or REST changes. See [TRAVEL_TIME_RUNOFF.md](TRAVEL_TIME_RUNOFF.md). **Sixteenth increment implemented:** separate asynchronous C++/REST coupled-reservoir simulation jobs with explicit calibrated control parameters and per-interval inflows, saved original-DEM junction validation, atomic checksummed time-series archives, restart-persistent status and bounded cached snapshot queries. The service does not yet generate temporal inflows automatically from saved rainfall scenarios. See [COUPLED_SIMULATION_SERVICE.md](COUPLED_SIMULATION_SERVICE.md). **Seventeenth increment implemented:** opt-in scenario-driven coupled simulation jobs using persistent Stage 7 runoff and explicit time-profile forcing; immediate or constant-velocity D8 delivery, leaf-reservoir identity validation, source SHA-256 provenance, separation of dry-domain runoff from hydraulic outlet discharge, and restart-readable statuses/snapshots. See [SCENARIO_COUPLED_FORCING.md](SCENARIO_COUPLED_FORCING.md). **Remaining:** surveyed/sourced control-section geometry and additional hydraulic laws (partial orifice flow, frictional culverts, backwater), automatic timed rainfall-to-coupled-simulation forcing, model-specific calibration provenance and policy-aware persisted cache keys, bounded async sensitivity APIs, metropolitan benchmarks and independent reference comparisons. See [RUNOFF_REDISTRIBUTION.md](RUNOFF_REDISTRIBUTION.md), [REDISTRIBUTION_CACHE.md](REDISTRIBUTION_CACHE.md) and [ASYNCHRONOUS_REDISTRIBUTION.md](ASYNCHRONOUS_REDISTRIBUTION.md).
9. **Complete service API and result formats.** Promote analysis/scenario APIs through the same application service, add HTTP presentation, windowed raster and vector output, progress/cancel, robust persistence and storage limits. **Exit:** identical results from in-process and HTTP clients and reusable cached terrain analysis.
10. **Metropolitan-scale benchmarks and integration readiness.** **First increment implemented:** opt-in, Qt-independent seeded synthetic raster benchmark executing actual D8 conditioning, original-DEM basin hierarchy and static redistribution; JSON stage timings, Linux process RSS, input fingerprint, basin counts, mass-balance validation, CLI limits and optional CTest smoke tests. See [BENCHMARKING.md](BENCHMARKING.md). **Second increment implemented:** opt-in Python-standard-library live Map → Hydrology HTTP harness, bounded analysis submission/polling, repeated persisted raster and basin-page timings, source-grade DEM parity against Map at identical cell centres, existing-job restart checks, optional local output-size inspection, preflight cell budgets and offline mock-server regression tests. The harness requires real running servers and does not ship benchmark measurements. **Field measurements completed:** live Map-sourced GLO-30 benchmarks at 3,525, 87,185 and 195,712 cells with exact DEM parity; persistent job stage timings identified hierarchy construction as the primary measured worker cost (688 ms of a 1,038 ms worker job for 195,712 cells). Per-row GeographicLib area memoization reduced actual 195,712-cell hierarchy time from 688 to 146 ms (single matched GLO-30 run), with whole-worker duration from 1,038 to 530 ms and unchanged basin counts/DEM window hashes. As a low-risk follow-up, the REST terrain reader now reuses one worker-local Qt network manager across its sequential Map patches (benchmarked once on the live service: request time was 225.26 ms before and 288.34 ms after; no performance benefit established). A follow-up now persists Map per-job request/copy/patch count diagnostics and exposes them in the live benchmark to separate source-call overhead from grid assembly, without a change to DEM output. Repeated live Map-sourced jobs now measure acquisition distributions and verify output identity; observed raster copies take roughly 0.13 ms while Map HTTP calls account for about 99.85% of terrain-fetch wall time. A read-only concurrency probe can replay identical saved-job source patches at 1/2/4 concurrent Map GET requests before modifying the production transport. The source scripts are explicitly included in repository ZIPs rather than accidentally ignored by a broad `benchmark*` rule. **Remaining:** remeasure source acquisition and larger city/metro regions with repetitions and peak server RAM, profile the new dominant fetch/D8 costs, test concurrent jobs, compare independently configured GRASS/WhiteboxTools results, and design out-of-core processing only if justified. **Exit:** repeatable field-realistic benchmark reports, documented numerical accuracy, tested resource limits and representative service-deployment performance.

## External integration checkpoints

- **Map:** Analysis-grade DEM windows are implemented by the accompanying authorized Map patch. Keep the Map and Hydrology patches separate and verify both are applied before integrated job tests.
- **Standalone:** Add the Hydrology repository as a submodule, link its reusable service library to GUI, and supply the existing Map library instance once separately authorized. Do not use localhost HTTP as an internal shortcut.
- **GUI:** Add the rainfall-region selection, scenario controls and visual layers only after API contracts are tested and changes are separately authorized.
- **SWMM:** No SWMM source code or solver in this roadmap. The hydrology result model must support later catchment and network export.

## Patch and documentation discipline

Changes stay inside `AOWIS-SERVER-HYDROLOGY`, with patch ZIPs named `aowis-server-hydrology-*.zip`, containing only changed/added files and retaining the root directory hierarchy. Extracted files must receive fresh timestamps. Update this roadmap and the README whenever architectural interfaces or implementation status change. Each stage must come with repeatable tests and explicit statements of what is already implemented versus still pending.
